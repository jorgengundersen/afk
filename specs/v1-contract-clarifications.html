V1 Contract Clarifications

This document tightens edge cases for the first Go implementation. If this page conflicts with the PRD, prefer the narrower v1 behavior here and update both documents before changing implementation scope.

1. CLI Parsing

  • The command separator -- is required.
  • Arguments before -- are afk flags.
  • Arguments after -- are the child command and its arguments.
  • afk never parses, removes, or rewrites arguments after --.
  • Unknown afk flags exit 2.
  • Missing child command exits 2.
  • -h and --help print usage to stdout and exit 0.
  • --version is deferred for v1.

2. Build and Toolchain

  • Use Go modules.
  • Use a current stable Go version; set go.mod to Go 1.22 or newer.
  • Build command: go build ./cmd/afk.
  • Test command: go test ./....
  • Linux and macOS are the only target platforms for v1.

3. Process IO

  • The main child command inherits stdin, stdout, and stderr.
  • --items-cmd runs as /bin/sh -c.
  • --items-cmd stdout is captured and parsed as items.
  • --items-cmd stderr is passed through to afk stderr.
  • --items-cmd stdin is closed or connected to an empty reader; it must not inherit interactive stdin.
  • Both main child commands and --items-cmd run in their own Unix process group.
  • --timeout, when set, applies to --items-cmd as well as the main child command.
  • Non-zero --items-cmd exit is an afk source error and exits 1.
  • Timed-out --items-cmd is an afk source error and exits 1; it is not affected by --fail.

4. Item Edge Cases

  • --items "" means no items and exits 0.
  • Whitespace-only newline text means no non-blank items and exits 0.
  • --items "[]" means no items and exits 0.
  • Static item sources never sleep.
  • Dynamic item source with no items in non-daemon mode and --empty-sleeps 0 exits 0.
  • Dynamic item source with no items in daemon mode sleeps and retries until interrupted.
  • Sleep retries do not increment AFK_INDEX.

5. JSON Item Parsing

  • If item source output is valid JSON and the top-level value is an array, parse it as a JSON array.
  • If item source output is invalid JSON, parse it as newline-delimited text.
  • If item source output is valid JSON but the top-level value is not an array, parse it as newline-delimited text.
  • JSON string elements become their string values.
  • JSON number, boolean, object, array, and null elements become compact JSON strings in AFK_ITEM.
  • Blank lines in newline-delimited text are ignored.

6. --until-success

  • --until-success is a failure policy, not a loop driver.
  • It still requires exactly one loop driver: --loops or --daemon.
  • For v1, --until-success is invalid with --items or --items-cmd.
  • With --loops N, try at most N times and stop early on the first exit 0.
  • With --daemon, retry until the first exit 0 or interrupt.
  • --until-success remains mutually exclusive with --fail stop.

8. Output Defaults

  • By default, afk prints no routine per-iteration status lines.
  • Child stdout and stderr pass through unchanged.
  • afk errors, timeout messages, and interrupt messages go to stderr.
  • afk never writes status/control text to stdout.

9. Validation Tightening

  • --sleep is valid only with --items-cmd.
  • --empty-sleeps is valid only with --items-cmd.
  • --loops and --daemon are mutually exclusive.
  • --loops and item sources are mutually exclusive.
  • --daemon and static --items are mutually exclusive.
  • --items and --items-cmd are mutually exclusive.
  • At least one loop driver is required: --loops, --daemon, --items, or --items-cmd.
  • All invalid combinations exit 2.
