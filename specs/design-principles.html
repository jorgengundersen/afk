Design Principles

This project is developed primarily by AI agents. The codebase is part of the prompt. Keep it small, current, explicit, and free of stale patterns.

1. Active Scope Wins

The active specs define the product. The PRD defines product scope; architecture and standards define implementation contract. For simplified afk, the core binary is only a generic loop runner.

Do not preserve or introduce agents, harnesses, models, prompts, beads workflows, structured child-output parsing, session logs, config files, or workflow orchestration.

2. Small Primitives, Thin Orchestration

Build small units with one clear contract. Prefer pure functions. Entry points parse input, call composed units, and surface results.

Primitives do. Orchestration decides.

3. Test the Contract

Tests are executable documentation. Prefer black-box tests for CLI behavior: exit codes, stdout/stderr passthrough, environment variables, timeouts, signals, and loop semantics.

Unit-test pure parsing and policy functions. Do not test implementation details unless they are the contract.

4. Prefer the Standard Library

Do not add dependencies by default. Use the standard library for flags, JSON, processes, time, and signals unless there is a strong reason not to.

Never add dependencies for removed scope: agents, prompts, beads clients, logging frameworks, config systems, renderers, or session management.

5. Errors Are Contracts

Fail fast and loudly. Create errors at the failure point, add context as they propagate, and handle them at entry points.

Distinguish child command failure from afk failure. Child exit codes are loop input. Invalid flags, source failures, timeout-management failures, and internal failures are afk errors.

6. Isolate External Boundaries

Shells, child processes, timers, signals, filesystems, and third-party packages enter through narrow boundaries. Domain logic uses project-owned types and simple values.

Add interfaces only when they earn their cost.

7. Minimal State and Configuration

Push state to the edges. Runtime state should be only what the loop contract requires: iteration index, current item batch, empty-sleep count, interrupt state, and last child exit when needed.

For v1, configuration is CLI flags only. No config files, persistent state, hidden workflow defaults, or session logs.

8. Output Is Not Observability

Main child stdout and stderr pass through unchanged. afk does not parse, render, summarize, or transform main child output.

afk does not print routine status by default. Required diagnostics are minimal and go to stderr. Never emit control/status output on stdout, except explicit help output. No file logging in v1.

9. Delete Before Abstracting

Build what the PRD defines, not a framework. Start concrete. Add abstraction only when the cost of not having it exceeds the cost of adding it.

During rewrites, prefer deleting old abstractions over adapting concepts from removed product scope.

10. Maintain the Prompt

Stale specs, examples, tests, and code patterns are context poison. If old code conflicts with the active PRD, the PRD wins.

Keep names discoverable, APIs obvious, tests illustrative, and patterns consistent.

Checklist

  1. Is this required by the active PRD?
  2. Does this unit have one nameable job?
  3. Can this be pure?
  4. Is this tested at the right boundary?
  5. Can this use the standard library?
  6. Is the error behavior explicit?
  7. Are external systems isolated?
  8. Is this state/configuration truly necessary?
  9. Does this preserve child output unchanged?
  10. Should old context be deleted instead?
