PRD: Simplified afk Loop Utility

Draft A radically simplified, general-purpose loop runner.

1. Product Summary

afk should be a small, general-purpose utility for repeatedly running a command. It should not know what the command does. It should not parse the command's output. It should not contain built-in support for agents, prompts, beads, structured JSON streams, or domain-specific workflows.

Core contract:

afk repeatedly executes one command. It may optionally choose iterations from an item list. It passes loop context via environment variables. It decides whether to continue based only on exit codes.

The CLI shape is:

afk [loop options] -- command [args...]

Everything after -- is the command to run. afk does not rewrite that command.

2. Goals

  • Run any command repeatedly.
  • Support fixed loop counts.
  • Support daemon mode: loop until interrupted.
  • Optionally drive loops from a static item list.
  • Optionally drive loops from a dynamic item-producing command.
  • Support newline-delimited and JSON-array item formats.
  • Sleep when a dynamic item source has no items.
  • Apply simple exit-code policies.
  • Support a per-iteration timeout so unattended loops cannot hang forever.

3. Non-goals

  • No built-in agent harnesses.
  • No prompt assembly.
  • No beads-specific client or workflow logic.
  • No structured output parsing or rendering.
  • No placeholder substitution such as {item}.
  • No file logging in v1.
  • No config files in v1.
  • No concurrency or parallel execution in v1.

4. CLI

afk [flags] -- command [args...]
FlagTypeDefaultDescription
-n, --loops integer Run the command a fixed number of times.
-d, --daemon boolean false Run until interrupted.
--items string Static item list. Parsed once before looping. Accepts JSON array or newline-delimited text.
--items-cmd shell command Dynamic item source. Re-run by afk to refresh available items. Stdout is parsed as JSON array or newline-delimited text.
--sleep duration 60s How long to sleep when --items-cmd returns no items.
--empty-sleeps integer 0 In non-daemon mode, how many times to sleep and retry after --items-cmd returns no items.
--fail continue or stop continue Whether a non-zero child exit code should stop the loop.
--until-success boolean false Retry until the command exits 0, then stop. Mutually exclusive with --fail stop.
--timeout duration none Maximum runtime for each spawned command invocation, including --items-cmd. No timeout when unset.

5. Run Modes

5.1 Fixed count

Run the command exactly N times unless interrupted, timed out, or stopped by failure policy.

afk -n 5 -- make test

5.2 Daemon

Run until interrupted. Without --items-cmd, daemon mode runs the command back-to-back with no built-in delay. If pacing is needed, put the sleep in the command.

afk -d -- ./worker

5.3 Static item list

--items provides an already-materialized list. It is parsed once. The command runs once per item. 

afk --items "$(cat my_list.txt)" -- ./worker
afk --items '["a","b","c"]' -- ./worker

5.4 Dynamic item command

--items-cmd provides a command that produces a list. afk runs this command to refresh available work. This is what makes daemon polling possible. 

afk -d --items-cmd "bd ready --json" --sleep 5m -- ./worker

Recommended behavior:

  • Run --items-cmd.
  • If it returns items, process the batch one item at a time.
  • In non-daemon mode, exit after processing the first non-empty batch.
  • In daemon mode, when the batch is exhausted, run --items-cmd again.
  • If it returns no items in daemon mode, sleep and retry forever.
  • If it returns no items in non-daemon mode, sleep and retry while --empty-sleeps quota remains, then exit 0 if no items were found.

6. Item Parsing

6.1 JSON array

If item source output is valid JSON and the top-level value is an array, each array element is one item.

  • String elements become their string value.
  • Number, boolean, object, array, and null elements become compact JSON in AFK_ITEM.
  • An empty array means no items.

6.2 Newline-delimited text

If item source output is not a JSON array, parse it as newline-delimited text.

  • Delimiter is \n.
  • Trailing final newline is ignored.
  • A line is blank if trimming Unicode whitespace leaves an empty string.
  • Blank lines are ignored.
  • Non-blank line content is preserved exactly except for line-ending removal.

6.3 Source exclusivity

Only one item source may be set:

  • --items
  • --items-cmd

7. Environment Variables

afk never rewrites the main child command. It passes loop context to main child invocations through environment variables.

VariableSet whenMeaning
AFK_INDEX Always 1-based global loop iteration number.
AFK_ITEM Item-driven loops Current item value. JSON objects/arrays are compact JSON.
AFK_ITEM_INDEX Item-driven loops 0-based index of the item within the current batch.
AFK_ITEM_COUNT Item-driven loops Total number of items in the current batch.

afk constructs each child environment from the parent environment plus loop context. It always overrides AFK_INDEX. In item-driven loops, it overrides AFK_ITEM, AFK_ITEM_INDEX, and AFK_ITEM_COUNT. In non-item loops, inherited AFK_ITEM, AFK_ITEM_INDEX, and AFK_ITEM_COUNT are removed so stale item context cannot leak into the child. --items-cmd receives the parent environment except these AFK_* loop-context variables are removed. 

afk --items '["apple","banana"]' -- sh -c 'echo "$AFK_INDEX $AFK_ITEM_INDEX/$AFK_ITEM_COUNT $AFK_ITEM"'

Expected output:

1 0/2 apple
2 1/2 banana

8. Sleep Semantics

In v1, --sleep only means: how long to wait when --items-cmd returns no items. It does not sleep between every successful loop iteration.

8.1 Daemon mode

afk -d --items-cmd "bd ready --json" --sleep 5m -- ./worker

If no items are returned, sleep for five minutes, then run --items-cmd again.

8.2 Non-daemon mode

afk --items-cmd "bd ready --json" --empty-sleeps 3 --sleep 30s -- ./worker

If no items are returned, sleep and retry up to three times. Sleeps do not count as command iterations.

8.3 Sleeping between all loops

No dedicated flag in v1. Users can put sleep in the command if needed: 

afk -n 10 -- sh -c './worker; sleep 5'

9. Failure Policy

For the main child command, afk only observes the exit code. Main child stdout and stderr are not interpreted.

PolicyBehaviorExample
--fail continue Non-zero exits are reported, but the loop continues. afk -n 20 --fail continue -- ./agent
--fail stop First non-zero exit stops the loop. afk exits with that code. afk -n 5 --fail stop -- go test ./...
--until-success Failures continue; first zero exit stops the loop with exit code 0. afk -d --until-success -- curl -f http://localhost:3000/health

Recommended final exit behavior:

  • --fail continue: exit 0 after completing the requested loop work, unless an internal/source error occurs.
  • --fail stop: exit with the first non-zero child exit code.
  • --until-success: exit 0 on first successful child exit; if fixed attempts are exhausted, exit with the last non-zero child exit code, or 1. For v1, this policy is valid only with --loops or --daemon, not item sources.
  • Interrupted by signal: exit 130.
  • Internal error, invalid config, source command failure, or timeout handling failure: exit 1 or 2 as appropriate.

10. Timeout

--timeout limits each command process group started by afk: both the main child command and --items-cmd. It prevents an unattended loop from getting stuck forever on one hung child process. 

afk -n 10 --timeout 30m -- ./worker

If the main child command times out, afk terminates the child process group and treats the iteration as synthetic child exit code 124, then handles it by the selected failure policy. If --items-cmd times out, it is an afk source error and exits 1.

11. Output

Main child stdout and stderr pass through directly. afk does not parse, render, or transform main child output. --items-cmd stdout is item-source data and is captured for parsing; its stderr passes through unchanged.

By default, afk prints no routine per-iteration status lines. Stdout belongs to the child command, except for explicit CLI help output such as --help. afk diagnostics, usage errors, timeout messages, interrupt messages, and other control output go to stderr and should be minimal.

No file logging in v1. If users need logs, they can redirect output or make the child command log for itself.

12. Signals and Process Management

  • On first interrupt, stop scheduling new iterations.
  • If a child command is running, terminate the child process group.
  • After a short grace period, kill the child process group if needed.
  • Exit with code 130 on user interrupt.

13. Validation Rules

  • A command after -- is required.
  • At least one loop driver is required: --loops, --daemon, --items, or --items-cmd.
  • --loops must be a positive integer.
  • --loops and --daemon are mutually exclusive.
  • --loops and item sources are mutually exclusive, because both determine iteration count.
  • --items and --items-cmd are mutually exclusive.
  • --daemon may be combined with --items-cmd.
  • --daemon and --items are mutually exclusive, to avoid replaying a static list forever.
  • Explicit --sleep is valid only with --items-cmd and must be non-negative.
  • Explicit --empty-sleeps is valid only with --items-cmd and must be non-negative.
  • --fail must be continue or stop.
  • --until-success is mutually exclusive with --fail stop.
  • --until-success requires --loops or --daemon and is invalid with item sources in v1.
  • --timeout, when set, must be positive.

14. Examples

Run a command five times

afk -n 5 -- echo hi

Run once per newline item

afk --items $'a\nb\nc' -- sh -c 'echo "$AFK_ITEM"'

Run once per JSON item

afk --items '[{"id":"a"},{"id":"b"}]' -- sh -c 'echo "$AFK_ITEM" | jq -r .id'

Poll a dynamic work source forever

afk -d --items-cmd "bd ready --json" --sleep 5m -- ./worker

Retry until a service is healthy

afk -d --until-success --timeout 15s -- sh -c 'curl -f http://localhost:3000/health || { sleep 10; exit 1; }'

Strict failure behavior

afk -n 5 --fail stop -- go test ./...

15. Migration from Current afk

Remove from the core binary:

  • --harness
  • --model
  • --raw
  • --harness-args
  • -p prompt handling
  • beads client integration
  • prompt assembly
  • structured output parsing/rendering
  • session log files

Domain-specific workflows move into wrapper scripts:

afk -d --items-cmd "bd ready --json" --sleep 5m -- ./work-on-one-bead

16. Acceptance Criteria

  • afk -n 3 -- echo hi prints hi three times and exits 0.
  • afk --items $'a\nb' -- sh -c 'echo "$AFK_ITEM"' prints a then b.
  • afk --items '["a","b"]' -- sh -c 'echo "$AFK_ITEM"' prints a then b.
  • afk --items-cmd "printf 'a\nb\n'" -- sh -c 'echo "$AFK_ITEM"' processes one non-empty dynamic batch, runs twice, and exits 0.
  • When --items-cmd returns no items in daemon mode, afk sleeps and retries.
  • When --items-cmd returns no items in non-daemon mode, afk respects --empty-sleeps.
  • AFK_INDEX is set for every main child invocation.
  • AFK_ITEM, AFK_ITEM_INDEX, and AFK_ITEM_COUNT are set for item-driven invocations.
  • --fail stop stops on the first non-zero child exit.
  • --until-success stops on the first zero child exit.
  • --timeout terminates a hung child process and applies failure policy.
  • Main child stdout/stderr are passed through without parsing or transformation.
  • Ctrl+C terminates the current child process group and exits 130.

17. Explicitly Deferred

  • --items-file — users can use --items "$(cat file)" or --items-cmd "cat file".
  • Placeholder substitution like {item}.
  • A dedicated interval flag for sleeping between every successful loop.
  • Quiet/verbose modes.
  • Dry-run mode.
  • File logging.
  • Config files.
  • Parallel execution.
